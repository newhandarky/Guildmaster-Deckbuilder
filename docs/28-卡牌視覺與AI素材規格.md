# 卡牌視覺與 AI 素材規格

## 目的與適用範圍

本文件定義專案卡片的統一外框比例、UI 顯示尺寸、版面分區，以及 AI 原創插畫的輸入與輸出規格。它只規範 Presentation／Appearance 層，不改變卡牌 mechanics、效果、數值、Snapshot、Replay 或 Rules Module。

本規格參考 [《冒險少女公會》官方網站的主遊戲卡片列表](https://www.paintcanfarm.com/aggboardgames/zh) 進行視覺觀察，但不保存、重製或提交任何官方卡圖、截圖、Logo、商標或卡面版型。所有正式遊戲素材必須為原創、AI 生成或具有明確授權紀錄的內容，並遵守 [內容與素材政策](./07-內容與素材政策.md) 與 [Presentation Pack 規格](./20-呈現包規格.md)。

## 卡片外框基準

所有卡片共用同一個直式外框，不因卡片類型改變寬高比。

| 項目 | 規格 |
| --- | --- |
| 標準比例 | `63:88` |
| CSS `aspect-ratio` | `63 / 88` |
| 寬／高小數比 | 約 `0.7159` |
| 高／寬小數比 | 約 `1.3968` |
| 參考實體尺寸 | `63 × 88 mm` |
| 參考 300 DPI 尺寸 | 約 `744 × 1039 px` |
| 含四周 3 mm 出血 | `69 × 94 mm`，約 `815 × 1110 px` |

`63 × 88 mm` 是依官方卡表視覺比例選定的專案基準，不是官網明文公布的實體製造尺寸。若未來要送印，必須再向實際印刷廠確認裁切、出血、圓角與安全區規格。

### Wireframe 工作座標與安全區

設計稿、Figma、Canvas 與切版討論統一使用 `630 × 880` 邏輯單位。這個座標剛好是 `63:88` 的十倍，容易換算百分比；它不是必須輸出的圖片解析度。

| 項目 | Wireframe 規格 |
| --- | --- |
| 工作畫布 | `630 × 880` 單位 |
| 內容安全區 | 四邊內縮 `24–32` 單位 |
| 重要文字／icon 最小邊距 | `32` 單位 |
| 可延伸背景／卡框區 | 安全區以外至卡片邊緣 |
| 成本／等級角標 | 約卡寬的 12%，固定在左上或右上，不占用獨立垂直列 |

所有卡名、規則文字、關鍵數值與互動狀態都必須留在安全區內。裝飾邊框、背景紋理與非必要插畫可以延伸到卡片邊緣。

### UI 顯示尺寸

| 使用情境 | 寬度 | 依比例計算的高度 |
| --- | ---: | ---: |
| 緊湊／手機卡片 | `112 px` | 約 `156 px` |
| 一般桌面卡片 | `146 px` | 約 `204 px` |
| 放大預覽卡片 | `252 px` | 約 `352 px` |

UI 應只控制卡片寬度，讓高度由 `aspect-ratio` 計算，不應在不同遊戲區域分別寫死寬度與高度。

```css
.card {
  flex: 0 0 146px;
  aspect-ratio: 63 / 88;
  min-height: 0;
}
```

若需要響應式寬度，可使用：

```css
.card {
  width: clamp(112px, 12vw, 146px);
  aspect-ratio: 63 / 88;
}
```

## 官網卡表版面觀察

觀察日期：2026-07-30。

官網主遊戲卡表共有七頁。各頁卡片都使用相同直式外框，但插畫與文字的垂直分配會因卡種及文字量調整。下表比例是從卡表畫面估算的「卡片總高度占比」，不是官方提供的像素標線；每列合計約為 100%。

| 卡片類型 | 官網卡表頁 | 插畫區約占 | 效果／說明文字約占 | 名稱、數值、圖示與邊框約占 | 觀察 |
| --- | ---: | ---: | ---: | ---: | --- |
| 冒險者 | 1 | 62–68% | 18–24% | 12–16% | 角色圖是主要視覺；底部保留較短的效果與數值區。 |
| 羈絆 | 2 | 52–60% | 24–30% | 14–18% | 插畫仍占過半，但效果區通常比冒險者更高。 |
| 物資／裝備／道具 | 3 | 50–58% | 26–32% | 14–18% | 物件插畫大致置中；底部需要穩定的規則文字空間。 |
| 魔王 | 4 | 48–55% | 28–34% | 14–18% | 戰力、獎勵等角落數值較醒目，文字區通常較密集。 |
| 魔物 | 5 | 50–58% | 24–31% | 14–18% | 與魔王接近，但部分卡片的規則文字較短。 |
| 協助者 | 6 | 52–66% | 20–34% | 10–14% | 官方卡表會依效果長度改變文字區；同一卡可能有簡易與完整文字版本。 |
| 起始牌／簡易資源／提示牌 | 7 | 72–82% | 0–15% | 10–18% | 無長效果文字的卡片接近全圖版型；提示牌是例外，不應當作一般遊戲卡模板。 |

官網觀察值用來了解不同卡種的視覺重心，不直接作為前端切版百分比。官方卡面有裝飾框、插畫延伸與部分疊圖，肉眼看見的插畫範圍會大於實際 UI `Art` 容器。專案模板必須優先確保數位版的文字可讀性與資訊掃描效率。

## 共通七區骨架

所有一般卡片由相同元件骨架組成，依卡種調整各區高度，不重新發明卡面結構：

1. `Header`：卡名、子類型與必要狀態。
2. `CostBadge`：成本、等級或門檻角標；覆蓋於 Header／Art 角落，不另占一列。
3. `Art`：只顯示原創／AI／授權插畫。
4. `TypeBanner`：卡片類型與最重要的分類 tag。
5. `RulesText`：時機 badge、效果摘要與規則文字。
6. `StatsReward`：戰力、討伐門檻、報酬、加成或其他關鍵數值。
7. `Footer`：系列、稀有度、穩定顯示 ID 或輔助 icon。

### 共通基準模板

最通用的 `standard` 模板採用以下比例，垂直區塊合計 100%：

| 區塊 | 高度占比 | `630 × 880` 參考高度 | 用途 |
| --- | ---: | ---: | --- |
| Header | 11% | 約 97 | 卡名、子類型；角標可疊於右側。 |
| Art | 46% | 約 405 | 主插畫，不放規則文字。 |
| Type Banner | 6% | 約 53 | 卡種與一個主要分類。 |
| Rules Text | 24% | 約 211 | Timing badge 與效果文字。 |
| Stats / Reward | 9% | 約 79 | 戰力、報酬或加成。 |
| Footer | 4% | 約 35 | 系列、ID 與輔助標記。 |

成本／等級角標約占卡寬 12%，屬於疊加元素，因此不計入上表的高度合計。角標不得遮住卡名、角色臉部或效果文字。

### 卡種模板變體

為避免相同卡種因文字長短而讓圖片忽大忽小，專案採固定模板；短文案留下空間，不自動放大插畫區。

| 模板 | Header | Art | Type Banner | Rules Text | Stats / Reward | Footer | 建議卡種 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| `character` | 10% | 50% | 6% | 21% | 9% | 4% | 冒險者 |
| `standard` | 11% | 46% | 6% | 24% | 9% | 4% | 羈絆、協助者 |
| `supply` | 10% | 42% | 6% | 29% | 9% | 4% | 物資、裝備、道具 |
| `enemy` | 10% | 44% | 6% | 26% | 10% | 4% | 魔物 |
| `boss` | 11% | 40% | 6% | 29% | 10% | 4% | 魔王或規則較複雜的敵人 |
| `full-art` | 8% | 68% | 5% | 8% | 7% | 4% | 無長效果文字的起始牌或特殊展示卡 |

一般卡片不得因為某張卡文字較少而切換模板。只有語意本來就不同的卡片種類，才可以使用不同模板。規則文字超出固定區域時，處理順序是縮短 presentation 文案、調整字級到允許下限、再使用詳情視窗；不可任意壓扁卡片或拉伸圖片。

## 卡種 Wireframe 與資訊優先順序

### 冒險者

資訊順序為名稱／成本、角色辨識、類型／職業、效果時機、戰力。右下角保留固定的大型戰力位置。

```text
┌────────────────────────────┐
│ 名稱                成本/星 │
├────────────────────────────┤
│                            │
│          插畫區            │
│                            │
├────────── 冒險者 ──────────┤
│ [入隊] 效果摘要             │
│ [持續] 效果摘要             │
├───────────────────────┬────┤
│ 職業 / Tag / 系列       │ 戰力 │
└───────────────────────┴────┘
```

### 裝備

資訊順序為裝備名稱／類型、物件辨識、配戴對象或限制、持續加成。加成值固定在 Stats 區，不能只寫在長段文字中。

```text
┌────────────────────────────┐
│ 名稱              裝備類型 │
├────────────────────────────┤
│         裝備插畫區          │
├────────── 裝備 ────────────┤
│ [配戴] 對象或條件           │
│ [持續] 效果摘要             │
├───────────────────────┬────┤
│ 裝備槽 / Tag            │ 加成 │
└───────────────────────┴────┘
```

### 道具

資訊順序為名稱、使用時機、立即效果與結算後去向。一次性或留場性質必須在相同位置表達。

```text
┌────────────────────────────┐
│ 名稱                  道具 │
├────────────────────────────┤
│         道具插畫區          │
├────────── 道具 ────────────┤
│ [使用] 時機                 │
│ 效果：摘要                  │
│ 結算後：留場 / 棄牌          │
├───────────────────────┬────┤
│ 消耗 / Tag              │ 狀態 │
└───────────────────────┴────┘
```

### 魔物

資訊順序為名稱、插畫辨識、討伐門檻、特殊效果、擊敗報酬。需求戰力與報酬分置 Stats 區兩側，讓玩家不必閱讀內文即可比較目標。

```text
┌────────────────────────────┐
│ 魔物名稱                   │
├────────────────────────────┤
│         魔物插畫區          │
├────────── 魔物 ────────────┤
│ [進場] 效果摘要             │
│ [擊敗時] 效果摘要           │
├───────────────┬────────────┤
│ 需求戰力       │ 報酬       │
└───────────────┴────────────┘
```

### 魔王

魔王使用獨立 `boss` 模板。Header、威脅識別與規則文字比一般魔物更醒目；複數階段或多部位狀態必須由專用詳情面板補充，不把所有狀態硬塞進縮圖卡面。

```text
┌────────────────────────────┐
│        魔王名稱        BOSS │
├────────────────────────────┤
│         魔王插畫區          │
├────────── 魔王 ────────────┤
│ [進場] 效果摘要             │
│ [持續] 效果摘要             │
│ [擊敗後] 效果摘要           │
├───────────────┬────────────┤
│ 討伐門檻       │ 特殊報酬    │
└───────────────┴────────────┘
```

### 羈絆／特殊資訊卡

這類卡以全局、回合或條件資訊為主，不強迫沿用戰力欄位。上半部保留圖像與標題，下半部使用條列式規則摘要；長期留場時增加回合提示，但仍由 `standard` 骨架組成。

## 文字、Badge 與資訊密度

### Wireframe 字級 Token

以下數值使用 `630 × 880` wireframe 單位，實作時需轉換為各顯示密度對應的 CSS token，不可直接當作 CSS pixel：

| Token | Wireframe 尺寸 | 用途 |
| --- | ---: | --- |
| `card-title` | 24–30 | 卡名，粗體。 |
| `card-banner` | 16–18 | 類型條與次要標題。 |
| `card-body` | 16–18 | 效果本文，左對齊，行高 1.3–1.45。 |
| `card-tag` | 12–14 | Timing badge、Footer 與輔助 tag。 |

文字不得疊在未遮罩的插畫上。規則文字一律左對齊；卡名、成本、戰力與報酬的位置跨卡片保持一致，建立固定掃描路徑。

### 響應式資訊密度

卡片縮小時不能只等比例縮小完整規則文字，否則手機與桌面牌列都會產生不可讀的小字：

| 顯示尺寸 | 卡面顯示內容 |
| --- | --- |
| `112 × 156 px` 緊湊卡 | 卡名短版、類型、插畫、成本／戰力／報酬與最多一個狀態 icon；完整規則由點擊／鍵盤開啟詳情。 |
| `146 × 204 px` 一般卡 | 卡名、類型、插畫、關鍵數值、Timing badge 與最多 2–3 行短效果摘要。 |
| `252 × 352 px` 放大卡 | 顯示完整 presentation 規則文字、所有必要 badge、tag 與數值。 |

所有必要資訊都必須能由鍵盤與螢幕閱讀器取得；不能只依 hover 顯示，也不能只以顏色區分類型或狀態。

### Timing Badge

可用 badge 包含 `入隊`、`進場`、`持續`、`討伐`、`擊敗時`、`此回合`、`休息階段`。它們只是顯示層的統一詞彙；只有已驗證 mechanics／presentation 明確提供對應時機時才能顯示，不可由 UI 根據卡名或效果文字自行推測。

- Badge 固定放在效果句前方。
- 相同語意使用相同名稱、形狀與位置。
- Badge 色彩必須有足夠對比，並同時保留文字，不能只以色相傳達。
- 同一卡面同時顯示的 Timing badge 原則上不超過三個；更多細節移至詳情面板。

### 類型配色

建議以低飽和色作辨識，實際色票由 Presentation Pack 決定：

| 類型 | 建議色彩方向 |
| --- | --- |
| 冒險者 | 暖色或中性金 |
| 裝備 | 藍灰 |
| 道具 | 綠或青 |
| 魔物 | 紫紅或深褐 |
| 魔王 | 深紅或黑金 |
| 羈絆／特殊 | 淡金或象牙白 |

類型色只協助辨識，不搶過名稱、數值、效果與插畫主體；任何狀態都必須同時具有文字、icon 或形狀差異。

## AI 原創插畫統一規格

### 原始生成檔

所有卡種優先使用同一種 AI 原始畫布，讓角色、魔物、物品與場景素材可以共用處理流程。

| 項目 | 規格 |
| --- | --- |
| 原始畫布 | `1536 × 2048 px` |
| 原始比例 | `3:4` 直式 |
| 色彩空間 | sRGB |
| 建議主檔格式 | PNG |
| Runtime 衍生格式 | WebP 或 AVIF |
| Runtime 建議尺寸 | `768 × 1024 px`；高解析預覽可保留 `1152 × 1536 px` |
| 最低品質 | 短邊不得小於 `1024 px` |

AI 只生成插畫，不生成卡框、名稱、規則文字、數字、icon、Logo、水印或簽名。這些元素全部由 UI／Presentation Pack 疊加，避免生成文字錯誤，也方便日後改版與多語系呈現。

### 構圖安全區

- 主體的臉、頭部、武器核心、物品辨識點或魔物弱點，應放在畫面中央約 70% 的安全區。
- 畫面外圍 10–15% 視為可裁切區，背景必須延伸到四邊。
- 角色頭頂與重要道具不要貼近上緣；卡片名稱列可能覆蓋插畫上方。
- 下方 15% 不放關鍵資訊；不同模板可能為效果區裁掉較多下半部。
- 插畫可使用 `object-fit: cover` 裁切，不可使用非等比例拉伸。
- 每個素材在 asset manifest 記錄建議焦點，例如 `objectPosition: "50% 38%"`，讓不同顯示尺寸維持相同構圖重心。

### 各卡種構圖 Brief

| 卡種 | 構圖要求 |
| --- | --- |
| 冒險者 | 角色占畫面約 60–75%；頭部落在上半部約三分之一處；臉部不貼上緣，腳部與武器末端不承載關鍵資訊。 |
| 裝備／道具 | 主體物件置中、輪廓清楚、背景簡單；物件辨識點位於中央安全區，避免小尺寸時與背景混在一起。 |
| 魔物／魔王 | 臉、核心器官或主要威脅點置中偏上；完整輪廓保留在中央 70%，底部不放必須辨識的肢體或弱點。 |
| 羈絆／多人場景 | 所有主要角色位於中央安全區；避免把兩名角色分置最左右兩側，以免 `4:5` 裁切失去人物。 |

### 顯示裁切

AI 主檔固定為 `3:4`，顯示時依模板裁切，不需要為每種卡片重新生成不同尺寸：

| 使用情境 | 建議插畫視窗比例 | 說明 |
| --- | --- | --- |
| 冒險者、協助者 | `4:5` | 保留人物上半身或全身姿勢，適合角色主視覺。 |
| 魔物、魔王 | `4:5` | 保留垂直壓迫感與完整輪廓。 |
| 物資、裝備、道具 | `1:1` 或 `4:5` | 物件使用近方形視窗；有人物持有或使用道具時使用 `4:5`。 |
| 羈絆／事件式插畫 | `4:5` | 兩名以上角色必須放在中央安全區，避免左右角色被裁掉。 |
| 全圖展示卡 | `3:4` | 最大程度保留 AI 原始構圖。 |

嚴禁把 `3:4` 原圖直接拉伸成卡片的 `63:88` 比例。卡片外框和插畫素材是兩個不同層級：卡片保持 `63:88`，插畫在卡片內依模板裁切。

## 前端元件與資料邊界

建議將卡面拆成可重用的顯示元件：

- `CardFrame`
- `CardHeader`
- `CardArt`
- `CardTypeBanner`
- `CardRules`
- `CardStats`
- `CardFooter`
- `TimingBadge`
- `ValueGem`

這些名稱是元件職責建議，不要求集中在單一檔案，也不授權繞過現有模組拆分規範。

UI adapter 可以組合 mechanics 與 Presentation Resolver 的輸出，產生只供渲染的 view model；不得新增另一套同時擁有規則與素材的權威 `CardData`：

```ts
interface CardVisualViewModel {
  definitionId: string;
  displayName: string;
  cardType: string;
  subtypeLabel?: string;
  template: 'character' | 'standard' | 'supply' | 'enemy' | 'boss' | 'full-art';
  imageAssetKey: string;
  shortDisplayText?: string;
  timingBadges: string[];
  objectPosition?: string;
}
```

成本、戰力、榮譽、報酬、合法性與效果仍來自 `CardDefinition`、GameState 與權威 query；圖片、顯示名稱、短文案、配色與裁切焦點來自 Presentation Pack。此 view model 不寫入 Snapshot／Replay，不得成為規則判定依據。

### MVP 模板優先順序

第一批 UI 實作先完成三套骨架：

1. `character`：冒險者。
2. `supply`：裝備與道具。
3. `enemy`：魔物；魔王先共用元件結構，再以 `boss` token 調整比例與視覺層級。

這三套先驗證文字可讀性、手牌縮圖辨識與場上數值掃描效率。羈絆、協助者與 `full-art` 等變體待對應功能進入 UI 範圍時再啟用。

## 素材命名與驗收

建議使用中性、穩定的 asset ID，不把官方角色名稱或規則數值寫入檔名：

```text
public-assets/generated/cards/
├── adventurer/
├── supply/
├── monster/
├── boss/
└── support/
```

每張 AI 素材至少驗收：

1. 原始尺寸、比例與色彩空間符合規格。
2. 沒有生成文字、Logo、水印、官方卡框或可辨識商標。
3. 主體落在安全區，使用 `4:5` 與 `1:1` 裁切時不會失去關鍵內容。
4. 縮小到 `112 × 156 px` 卡片時仍能辨識主體。
5. 與同一 Presentation Pack 的 palette、光源、描線、視角與背景密度一致。
6. manifest 記錄生成日期、工具／模型、prompt brief 版本、人工修改與素材權利狀態。
7. `112 × 156 px` 與 `146 × 204 px` 不呈現不可讀的完整小字；必要規則可透過詳情面板存取。
8. 卡片類型、互動狀態與 Timing badge 不只依賴顏色傳達。
