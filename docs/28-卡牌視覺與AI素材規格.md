# 卡牌視覺與 AI 素材規格

## 目的與適用範圍

本文件定義專案卡片的統一外框比例、UI 顯示尺寸、版面分區，以及 AI 原創插畫的輸入與輸出規格。它只規範 Presentation／Appearance 層，不改變卡牌 mechanics、效果、數值、Snapshot、Replay 或 Rules Module。

本規格參考 [《冒險少女公會》官方網站的主遊戲卡片列表](https://www.paintcanfarm.com/aggboardgames/zh) 進行視覺觀察，但不保存、重製或提交任何官方卡圖、截圖、Logo、商標或卡面版型。所有正式遊戲素材必須為原創、AI 生成或具有明確授權紀錄的內容，並遵守 [內容與素材政策](./07-內容與素材政策.md) 與 [Presentation Pack 規格](./20-呈現包規格.md)。

## 卡片外框基準

所有卡片共用同一個直式外框，不因卡片類型改變寬高比。

| 項目 | 規格 |
| --- | --- |
| 標準比例 | `63:88` |
| CSS `aspect-ratio` | `63 / 88` |
| 寬／高小數比 | 約 `0.7159` |
| 高／寬小數比 | 約 `1.3968` |

`63:88` 是網頁卡片外框的統一顯示比例。

### Wireframe 工作座標與安全區

設計稿、Figma、Canvas 與切版討論統一使用 `630 × 880` 邏輯單位。這個座標剛好是 `63:88` 的十倍，容易換算百分比；它不是必須輸出的圖片解析度。

| 項目 | Wireframe 規格 |
| --- | --- |
| 工作畫布 | `630 × 880` 單位 |
| 內容安全區 | 四邊內縮 `24–32` 單位 |
| 重要文字／icon 最小邊距 | `32` 單位 |
| 可延伸背景／卡框區 | 安全區以外至卡片邊緣 |
| 成本／等級角標 | 約卡寬的 12%，固定在左上或右上，不占用獨立垂直列 |

所有卡名、規則文字、關鍵數值與互動狀態都必須留在安全區內。裝飾邊框、背景紋理與非必要插畫可以延伸到卡片邊緣。

### UI 顯示尺寸

| 使用情境 | 寬度 | 依比例計算的高度 |
| --- | ---: | ---: |
| 緊湊／手機卡片 | `112 px` | 約 `156 px` |
| 一般桌面卡片 | `146 px` | 約 `204 px` |
| 放大預覽卡片 | `252 px` | 約 `352 px` |

UI 應只控制卡片寬度，讓高度由 `aspect-ratio` 計算，不應在不同遊戲區域分別寫死寬度與高度。

```css
.card {
  flex: 0 0 146px;
  aspect-ratio: 63 / 88;
  min-height: 0;
}
```

若需要響應式寬度，可使用：

```css
.card {
  width: clamp(112px, 12vw, 146px);
  aspect-ratio: 63 / 88;
}
```

## 官網卡表版面觀察

觀察日期：2026-07-30。

官網主遊戲卡表共有七頁。各頁卡片都使用相同直式外框，但插畫與文字的垂直分配會因卡種及文字量調整。下表比例是從卡表畫面估算的「卡片總高度占比」，不是官方提供的像素標線；每列合計約為 100%。

| 卡片類型 | 官網卡表頁 | 插畫區約占 | 效果／說明文字約占 | 名稱、數值、圖示與邊框約占 | 觀察 |
| --- | ---: | ---: | ---: | ---: | --- |
| 冒險者 | 1 | 62–68% | 18–24% | 12–16% | 角色圖是主要視覺；底部保留較短的效果與數值區。 |
| 羈絆 | 2 | 52–60% | 24–30% | 14–18% | 插畫仍占過半，但效果區通常比冒險者更高。 |
| 物資／裝備／道具 | 3 | 50–58% | 26–32% | 14–18% | 物件插畫大致置中；底部需要穩定的規則文字空間。 |
| 魔王 | 4 | 48–55% | 28–34% | 14–18% | 戰力、獎勵等角落數值較醒目，文字區通常較密集。 |
| 魔物 | 5 | 50–58% | 24–31% | 14–18% | 與魔王接近，但部分卡片的規則文字較短。 |
| 協助者 | 6 | 52–66% | 20–34% | 10–14% | 官方卡表會依效果長度改變文字區；同一卡可能有簡易與完整文字版本。 |
| 起始牌／簡易資源／提示牌 | 7 | 72–82% | 0–15% | 10–18% | 無長效果文字的卡片接近全圖版型；提示牌是例外，不應當作一般遊戲卡模板。 |

官網觀察值用來了解不同卡種的視覺重心，不直接作為前端切版百分比。官方卡面有裝飾框、插畫延伸與部分疊圖，肉眼看見的插畫範圍會大於實際 UI `Art` 容器。專案模板必須優先確保數位版的文字可讀性與資訊掃描效率。

## Art-first 分層卡面

專案採「美術優先、資訊漸進揭露」的卡面。AI 插畫是滿版底層，卡名、關鍵數值與極短摘要以半透明漸層疊加；完整規則放在卡片外的詳情面板。這比把卡片切成多個不透明矩形區更能保留插畫，也避免把所有效果硬壓成難記的 icon。

### 永久顯示層

1. `ArtBase`：滿版原創／AI／授權插畫，占整張卡片。
2. `TitleScrim`：上緣漸層，顯示卡名、卡種與成本／等級。
3. `MetricRail`：固定在左側或右側的窄列，只放最多三個高頻數值 icon。
4. `SummaryBand`：下緣漸層，顯示一個 Timing badge、最多一行短摘要與主要戰力／報酬。
5. `StateRing`：選取、可用、不可用、目標與危險狀態，以外框、形狀與文字共同表示。

### 漸進揭露層

6. `QuickPeek`：滑鼠 hover 或鍵盤 focus 時，在卡片旁顯示不遮住卡圖的浮動摘要；它只是效率增強，不是資訊唯一入口。
7. `CardDetailsPanel`：點擊、觸控或按 Enter／Space 後固定開啟。桌面使用側欄／popover，手機使用 bottom sheet，提供完整規則、所有標籤與可執行動作。

### 覆蓋比例

以下百分比是覆蓋層相對卡片的高度或寬度；它們彼此重疊，因此不需要合計 100%。

| 模板 | 上方名稱漸層 | 下方摘要漸層 | 側邊數值列寬度 | 中央不被資訊元件遮擋的高度 | 建議卡種 |
| --- | ---: | ---: | ---: | ---: | --- |
| `character` | 10% | 18% | 12% | 約 72% | 冒險者 |
| `standard` | 10% | 20% | 12% | 約 70% | 羈絆、協助者 |
| `supply` | 10% | 20% | 12% | 約 70% | 物資、裝備、道具 |
| `enemy` | 10% | 22% | 14% | 約 68% | 魔物 |
| `boss` | 11% | 24% | 14% | 約 65% | 魔王或規則較複雜的敵人 |
| `full-art` | 8% | 12% | 10% | 約 80% | 無長效果文字的起始牌或特殊展示卡 |

名稱與摘要使用由透明到深色的漸層，不使用整片不透明底板。插畫仍可在覆蓋層後方延伸，但臉部、核心器官與物品辨識點必須落在中央不遮擋區。

### 各卡種保留資訊

| 卡種 | 卡面永久顯示 | 詳情面板顯示 |
| --- | --- | --- |
| 冒險者 | 名稱、成本、職業／類型、戰力、最多一個主要 Timing badge | 完整入隊／持續／討伐效果、其他 tag 與限制。 |
| 裝備 | 名稱、裝備類型、主要加成、最多一個配戴限制 icon | 可配戴對象、持續效果、裝備槽與所有限制。 |
| 道具 | 名稱、使用時機 badge、主要效果值、一次性／留場狀態 | 完整效果、結算後去向與例外條件。 |
| 魔物 | 名稱、需求戰力、主要報酬、危險狀態 | 進場／擊敗時效果、完整報酬與討伐限制。 |
| 魔王 | 名稱、BOSS 標記、討伐門檻、主要報酬／階段 | 進場、持續、擊敗後、多階段或多部位完整資訊。 |
| 羈絆／特殊 | 名稱、條件進度或狀態、一行摘要 | 完整全局／回合條件與規則說明。 |

一般卡片不得因為文字較少就臨時放大覆蓋層，也不得讓一張卡出現超過三個永久數值 icon。卡面摘要超出一行時，縮短 presentation 文案或只保留 Timing badge；完整內容永遠由詳情面板提供。

### Icon 使用邊界

Icon 適合表達玩家會反覆比較、語意固定且能立即辨識的數值：

- 招募／購買成本。
- 戰力或討伐門檻。
- 榮譽、金錢或固定報酬。
- 裝備加成。
- 已建立穩定詞彙的卡種類型與 Timing badge。

以下資訊不得只用 icon 取代：

- 多步驟效果與結算順序。
- 條件、例外、目標範圍或「若／否則」分支。
- 效果結算後的卡片去向。
- 需要玩家同意、選擇或回應的 lifecycle。
- 尚未建立全遊戲一致詞彙的單卡特殊能力。

數值 icon 是資訊顯示，不是各自獨立的小按鈕；整張卡或明確的主要動作按鈕才是互動目標。每個 icon 在詳情面板都必須有文字標籤，不能要求玩家背誦圖示。

### Lifecycle Interaction Dock

需要玩家選擇或同意的 continuation 使用非 modal、sticky dock。卡牌在 pending 期間仍可開啟詳情，但只有 session 提供的完整 legal Commands 能成為動作；UI 不重建 command、不解析 Effect AST，也不顯示未經 PlayerView 公開的 counter 值。

choice／policy 的人類可讀文案由 Web-local resolver 以 stable ID 對應；缺漏時顯示中性 fallback 與原始 option ID，不猜測規則語意。拒絕、取消與 explicit expiration 使用可撤銷的本機二次確認；Escape 只退出確認，不關閉強制互動。explicit expiration 是確定性規則 command，不加入 wall-clock 倒數。

## 文字、Badge 與資訊密度

### Wireframe 字級 Token

以下數值使用 `630 × 880` wireframe 單位，實作時需轉換為各顯示密度對應的 CSS token，不可直接當作 CSS pixel：

| Token | Wireframe 尺寸 | 用途 |
| --- | ---: | --- |
| `card-title` | 24–30 | 卡名，粗體。 |
| `card-metric` | 18–22 | 成本、戰力與報酬數值。 |
| `card-summary` | 16–18 | 卡面一行摘要，左對齊，行高 1.3–1.45。 |
| `card-tag` | 12–14 | Timing badge、類型與輔助 tag。 |

文字只可疊在具有足夠對比的漸層／scrim 上，不得直接落在高細節插畫上。摘要與詳情規則文字一律左對齊；卡名、成本、戰力與報酬的位置跨卡片保持一致，建立固定掃描路徑。

### 響應式資訊密度

卡片縮小時不能只等比例縮小完整規則文字，否則手機與桌面牌列都會產生不可讀的小字：

| 顯示尺寸 | 卡面顯示內容 |
| --- | --- |
| `112 × 156 px` 緊湊卡 | 卡名短版、滿版插畫、成本／戰力／報酬與最多一個狀態 icon；不在卡面顯示效果內文。 |
| `146 × 204 px` 一般卡 | 卡名、滿版插畫、最多三個關鍵數值、Timing badge 與一行短摘要。 |
| `252 × 352 px` 放大卡 | 保留 art-first 卡面，可顯示兩行摘要；完整規則仍放在相鄰詳情面板，避免放大卡重新變成文字牆。 |

所有必要資訊都必須能由鍵盤與螢幕閱讀器取得；不能只依 hover 顯示，也不能只以顏色區分類型或狀態。

### Responsive Game Table Shell

MVP 使用單頁空間式牌桌，不以 tabs 或預設收合隱藏合法遊戲區域。DOM 與鍵盤順序固定為：對局／玩家狀態、公共遭遇、酒館、玩家隊伍、手牌、interaction rail、事件與診斷。桌面可將活動紀錄放在右側 rail，但不得以 CSS reorder 改變讀取順序。

- `>= 1180 px`：主遊戲區與約 `300 px` activity rail 雙欄；遭遇與酒館並排。
- `768–1179 px`：單一主欄，足夠寬度時公共區可並排，activity 接在遊戲區之後。
- `<= 767 px`：使用 `112 × 156 px` compact card 與單欄版面。
- 橫向且高度 `<= 500 px`：同樣使用 compact card；interaction rail 可自行垂直捲動，詳情維持 side sheet。

只有卡牌列可以水平捲動，所有 grid child 必須允許縮至 viewport；Replay 診斷使用預設收合的 native `details`，事件紀錄則維持正常遊戲資訊。lifecycle 與一般回合控制共用同一 sticky interaction rail，不能形成互相覆蓋的兩個固定面板。

### Hover、點擊與觸控

不採用「hover 才能知道卡片效果」的設計。建議互動如下：

- 滑鼠 hover：延遲約 250–400 ms 顯示相鄰 `QuickPeek`，只含卡名、關鍵數值與 1–2 行摘要；移出後可關閉。
- 鍵盤 focus：顯示與 hover 相同的 `QuickPeek`，Enter／Space 固定開啟詳情。
- 點擊／觸控卡片：開啟或固定 `CardDetailsPanel`；手機使用 bottom sheet。
- Escape、關閉按鈕或點擊明確的背景區域：關閉詳情並把焦點送回原卡片。
- 完整規則、目標、限制與主要動作都能在 `CardDetailsPanel` 操作，不要求 hover。

MVP 先實作「點擊／觸控開啟詳情＋面板內主要動作」，暫不做 hover 展開動畫與卡面內多個小按鈕。這會多一次確認點擊，但可避免誤出牌、誤購買或誤討伐，且觸控、滑鼠與鍵盤行為一致。若可用性測試證明高頻操作過慢，再在卡片下方摘要帶加入單一、至少 `40 × 40 px` 的直接動作按鈕；不得使用雙擊作為必要操作。

### Timing Badge

可用 badge 包含 `入隊`、`進場`、`持續`、`討伐`、`擊敗時`、`此回合`、`休息階段`。它們只是顯示層的統一詞彙；只有已驗證 mechanics／presentation 明確提供對應時機時才能顯示，不可由 UI 根據卡名或效果文字自行推測。

- Badge 固定放在效果句前方。
- 相同語意使用相同名稱、形狀與位置。
- Badge 色彩必須有足夠對比，並同時保留文字，不能只以色相傳達。
- 同一卡面永久顯示的 Timing badge 原則上不超過一個；`QuickPeek` 最多兩個，更多細節移至詳情面板。

### 類型配色

建議以低飽和色作辨識，實際色票由 Presentation Pack 決定：

| 類型 | 建議色彩方向 |
| --- | --- |
| 冒險者 | 暖色或中性金 |
| 裝備 | 藍灰 |
| 道具 | 綠或青 |
| 魔物 | 紫紅或深褐 |
| 魔王 | 深紅或黑金 |
| 羈絆／特殊 | 淡金或象牙白 |

類型色只協助辨識，不搶過名稱、數值、效果與插畫主體；任何狀態都必須同時具有文字、icon 或形狀差異。

## AI 原創插畫統一規格

### 原始生成檔

所有卡種優先使用同一種 AI 原始畫布，讓角色、魔物、物品與場景素材可以共用處理流程。

| 項目 | 規格 |
| --- | --- |
| 原始畫布 | `1536 × 2048 px` |
| 原始比例 | `3:4` 直式 |
| 色彩空間 | sRGB |
| 建議主檔格式 | PNG |
| Runtime 衍生格式 | WebP |
| Runtime 固定尺寸 | `384 × 512 px` 與 `768 × 1024 px` |
| 最低品質 | 短邊不得小於 `1024 px` |

AI 只生成插畫，不生成卡框、名稱、規則文字、數字、icon、Logo、水印或簽名。這些元素全部由 UI／Presentation Pack 疊加，避免生成文字錯誤，也方便日後改版與多語系呈現。

### 構圖安全區

- 主體的臉、頭部、武器核心、物品辨識點或魔物弱點，應放在畫面中央約 65–70% 的安全區。
- 畫面外圍 10–15% 視為可裁切區，背景必須延伸到四邊。
- 角色頭頂與重要道具不要貼近上方 12%；`TitleScrim` 會覆蓋插畫上緣。
- 下方 25% 不放唯一的關鍵資訊；`SummaryBand` 與主要數值可能覆蓋該區。
- `MetricRail` 所在側的外緣 14% 不放臉部、武器核心或物品辨識點。
- 插畫可使用 `object-fit: cover` 裁切，不可使用非等比例拉伸。
- 每個素材在 asset manifest 記錄建議焦點，例如 `objectPosition: "50% 38%"`，讓不同顯示尺寸維持相同構圖重心。

### 各卡種構圖 Brief

| 卡種 | 構圖要求 |
| --- | --- |
| 冒險者 | 角色占畫面約 60–75%；頭部落在上半部約三分之一處；臉部不貼上緣，腳部與武器末端不承載關鍵資訊。 |
| 裝備／道具 | 主體物件置中、輪廓清楚、背景簡單；物件辨識點位於中央安全區，避免小尺寸時與背景混在一起。 |
| 魔物／魔王 | 臉、核心器官或主要威脅點置中偏上；完整輪廓保留在中央 70%，底部不放必須辨識的肢體或弱點。 |
| 羈絆／多人場景 | 所有主要角色位於中央安全區；避免把兩名角色分置最左右兩側，以免滿版卡面裁切失去人物。 |

### 顯示裁切

AI 主檔固定為 `3:4`；art-first 卡面使用整張 `63:88` 卡片作為插畫視窗，以 `object-fit: cover` 等比例裁切。`3:4` 與 `63:88` 接近，轉換時只會裁掉少量左右內容；主體仍必須遵守中央安全區。

| 使用情境 | 插畫視窗比例 | 說明 |
| --- | --- | --- |
| 一般卡面 | `63:88` | 滿版 `ArtBase`，上下疊加漸層資訊。 |
| 詳情面板主圖 | `3:4` | 優先完整呈現 AI 原始構圖。 |
| 物資／道具特寫 | 可選 `1:1` | 只在詳情面板或素材瀏覽器使用，不改變卡面外框。 |

嚴禁把 `3:4` 原圖直接拉伸成 `63:88`。卡片外框與插畫素材是兩個層級：卡片保持 `63:88`，插畫等比例放大後裁切，並以 `objectPosition` 保存構圖焦點。

## 前端元件與資料邊界

建議將卡面拆成可重用的顯示元件：

- `CardFrame`
- `CardArt`
- `CardTitleScrim`
- `CardMetricRail`
- `CardSummaryBand`
- `CardStateRing`
- `CardQuickPeek`
- `CardDetailsPanel`
- `TimingBadge`
- `ValueGem`

這些名稱是元件職責建議，不要求集中在單一檔案，也不授權繞過現有模組拆分規範。

UI adapter 可以組合 mechanics 與 Presentation Resolver 的輸出，產生只供渲染的 view model；不得新增另一套同時擁有規則與素材的權威 `CardData`：

```ts
interface CardVisualViewModel {
  definitionId: string;
  displayName: string;
  cardType: string;
  subtypeLabel?: string;
  template: 'character' | 'standard' | 'supply' | 'enemy' | 'boss' | 'full-art';
  imageAssetKey: string;
  shortDisplayText?: string;
  timingBadges: string[];
  objectPosition?: string;
}
```

成本、戰力、榮譽、報酬、合法性與效果仍來自 `CardDefinition`、GameState 與權威 query；圖片、顯示名稱、短文案、配色與裁切焦點來自 Presentation Pack。此 view model 不寫入 Snapshot／Replay，不得成為規則判定依據。

### MVP 模板優先順序

第一批 UI 實作先完成三套骨架：

1. `character`：冒險者。
2. `supply`：裝備與道具。
3. `enemy`：魔物；魔王先共用元件結構，再以 `boss` token 調整比例與視覺層級。

這三套先共用同一套滿版插畫、名稱漸層、數值列、摘要帶與詳情面板，驗證插畫辨識、場上數值掃描、點擊確認成本與手機 bottom sheet。MVP 不實作 icon-only 效果語言，也不把 hover 當成必要路徑。羈絆、協助者與 `full-art` 等變體待對應功能進入 UI 範圍時再啟用。

## 素材命名與驗收

建議使用中性、穩定的 asset ID，不把官方角色名稱或規則數值寫入檔名：

```text
public-assets/generated/cards/
├── adventurer/
├── supply/
├── monster/
├── boss/
└── support/
```

每張 AI 素材至少驗收：

1. 原始尺寸、比例與色彩空間符合規格。
2. 沒有生成文字、Logo、水印、官方卡框或可辨識商標。
3. 主體落在安全區，使用卡面 `63:88` 與詳情 `3:4` 呈現時不會失去關鍵內容。
4. 縮小到 `112 × 156 px` 卡片時仍能辨識主體。
5. 與同一 Presentation Pack 的 palette、光源、描線、視角與背景密度一致。
6. manifest 記錄生成日期、工具／模型、prompt brief 版本、參考來源聲明、素材權利狀態、人工 approved 紀錄及兩種 runtime SHA-256。
7. `112 × 156 px` 與 `146 × 204 px` 不呈現不可讀的完整小字；必要規則可透過詳情面板存取。
8. 卡片類型、互動狀態與 Timing badge 不只依賴顏色傳達。
9. 關閉詳情後焦點回到原卡片；手機與鍵盤不依賴 hover。
10. 永久卡面最多三個數值 icon 與一個 Timing badge，特殊效果不以未定義 icon 取代。

## 增量接入流程

Presentation Pack 先為全部 demo definition ID 配置與檔名無關的 stable asset key；asset manifest 可以只核准其中一部分。缺圖時卡面與詳情沿用 CSS placeholder，不阻擋 build、遊戲、Snapshot 或 Replay。每筆 approved record 必須有 `384×512`／`768×1024` WebP、`objectPosition`、SHA-256、alt text 對應、來源／授權與人工審核；React 只消費 resolver 組合後的 `src`／`srcSet`，不直接讀 manifest。

素材批次固定為：

1. starter＋冒險者。
2. 道具＋裝備。
3. 魔物。
4. 魔王。

每批使用獨立小型 PR，只加入已核准 WebP、manifest record、alt text、焦點、權利紀錄與視覺 regression；不等待全卡完成才啟用已核准素材。公開發行前仍必須完成原創品牌、Logo／商標及整體權利審查。

卡牌 UI 的 accessibility baseline 不依賴插畫是否完成：每張卡均可由鍵盤開啟詳情，accessible name 包含卡種、永久數值、互動狀態，以及 session 提供時的具體合法動作；名稱仍明示卡片按鈕只會開啟詳情，authoritative Command 必須在詳情內確認。全域操作具明確 focus-visible 與至少 `44×44px` 目標。主牌桌提供 skip link，details／lifecycle／重新開局確認在 Escape 或取消後恢復到原操作點，結算畫面以有序列表呈現排名並將焦點交給「開啟新遠征」，重開後再回到回合提示；另以 `1280×800` 桌機鍵盤 journey、`320px` reflow、200% 文字放大、reduced motion、forced colors 及 WCAG A／AA automated gate 持續回歸。

這些項目可以在後續視覺設計 PR 補充，但不得改變本文件的卡片外框比例，除非另有明確設計決策與全 UI migration 計畫。
