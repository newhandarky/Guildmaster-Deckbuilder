# 系統架構

本文件描述完整產品的目標架構，適用於基礎版、Vol.1、多部位究極魔神、後續擴充、AI 與線上對戰。MVP 只先啟用其中一部分 Content Pack／Rules Module 與 local runtime adapter，不建立另一套縮水架構。

## 技術選型

- Workspace：pnpm workspace
- 共用語言：TypeScript（strict mode）
- Web client：React + Vite
- UI state：React local state；跨畫面 application state 使用 Zustand
- 規則／通訊資料驗證：Zod
- 樣式：Tailwind CSS 與專案 design tokens
- 單元／整合測試：Vitest + React Testing Library
- 瀏覽器流程測試：Playwright
- MVP 儲存：localStorage，保留切換 IndexedDB 的 adapter
- 線上 transport：目標採 HTTP snapshot/recovery + WebSocket 即時事件；M10 才選 server framework 與資料庫

套件版本在建立工程時鎖入 lockfile。server framework、資料庫與部署平台在真正實作線上階段再以 ADR 選擇，避免現在猜測基礎設施；domain contract 不等待這些決定。

## Runtime 邊界

```text
                         ┌─────────────────────┐
                         │ packages/content-*  │
                         └──────────┬──────────┘
                                    ▼
┌──────────────┐ commands  ┌─────────────────────┐  snapshots/events
│ apps/web UI  │──────────▶│ GameSession contract│──────────────────┐
└──────────────┘◀──────────│ game-protocol DTOs  │◀─────────────────┘
                  views     └─────────┬───────────┘
                          local       │ remote
                    ┌─────────────────┴─────────────────┐
                    ▼                                   ▼
          LocalGameSession                    RemoteGameSession
                    │                                   │ HTTP/WS
                    ▼                                   ▼
        packages/game-engine            apps/server authoritative room
                                                        │
                                                        ▼
                                             packages/game-engine
```

`GameSession` 是 web feature 唯一可見的對局入口。local 與 remote adapter 必須回傳相同的 command result、player view、event 與 error DTO，因此線上化不需要重寫 UI。

Rules Module 的泛用 `BondCondition` runtime 亦位於 engine 邊界：module 只註冊 JSON-only 規則，純 evaluator 同時供 query 與 reducer 使用。`BOND_COMPLETED` 仍是既有 post-command transaction 的 fact，因此 lifecycle choice 的 Snapshot resume 會續跑既有 cursor，不會重複完成羈絆或產生事件。

UI 另經由 `PresentationResolver` 將 `CardDefinition.id` 解析為純顯示 view model；resolver 不參與 Command、Event、規則計算或 session authority。

## Package 責任與依賴

```text
apps/web ─────────────▶ game-protocol
   │                         ▲
   ├──────────────▶ content-base
   │                         │
   └─ local adapter ─▶ game-engine ◀── content-* extensions

apps/server ──────────▶ game-protocol
   ├──────────────────▶ game-engine
   └──────────────────▶ approved content-*

game-ai ──────────────▶ game-protocol + game-engine public queries
game-engine ──────────▶ game-protocol types only
content-* ────────────▶ game-engine extension API + game-protocol schemas
```

- package 間只能使用 package exports，不得 import 另一 package 的 `src/*`。
- `game-engine` 不 import React、browser/server API 或具體 content pack。
- `apps/web` 與 `apps/server` 不互相 import。
- 共享程式不得放進 app 再由另一 app deep import；應提升至責任明確的 package。
- 禁止循環依賴。內部模組與檔案規範見 `11-模組化與檔案拆分規範.md`。

## 核心 contracts

### Engine

- `composeRuleset(contentPacks, moduleConfigs): RulesetRegistry`
- `createGame(config, registry, seed): GameState`
- `dispatch(state, commandEnvelope, context): EngineResult`
- `getLegalCommands(state, actorId): LegalCommand[]`
- `projectView(state, viewer): PlayerView`
- `serializeSnapshot(state): VersionedSnapshot`
- `restoreSnapshot(snapshot, registry): GameState`
- `replay(initialConfig, commandEnvelopes, registry): ReplayResult`

所有入口皆為確定性純邏輯。合法性由 engine 判斷，不信任 UI 或 client。

### Effect execution boundary

`game-protocol` 定義版本化 JSON Effect AST、lifecycle hook／payload 與 Command Replay bundle；`game-engine/effects` 提供 executor、原子 card movement、transactional lifecycle dispatcher 與從 initial config 重放既有 `dispatch` 的 replay runtime。Rules Module 只能註冊可序列化 hook data 與 Effect AST，不能以 callback 直接寫 `GameState`。choice 以 pending state 暫停，random 使用權威 `rngState`；replacement 只在 `event-before`，event trigger 在 `event-after`，相同 priority 或沒有明確順序時回傳 `ORDER_POLICY_REQUIRED`，不能猜測。

pending lifecycle continuation 將 payload、context、目前／剩餘 hook refs、registry/module version 與 rollback checkpoint 放進 Snapshot。`RESOLVE_EFFECT_CHOICE` 恢復後繼續相同 queue；unknown module/hook/version 明確失敗。continuous hook 此階段只回報可測的 evaluation boundary，不套用任何卡牌持續效果。

成功 command 會在同一 authoritative transaction 內發出 command 與 reducer fact 的 lifecycle boundaries。事件 hook 可用 `eventType` filter，避免未指定的規則誤套用到所有 facts。

command-before choice continuation 已實作：原 command envelope 與 lifecycle registry 指紋以純資料保存在 Snapshot，恢復後不重跑已完成 hook 或重複 reducer facts。

`engine/post-command-pipeline.ts` 將 reducer 後流程建模為可續跑 state machine：`event-before(fact i)` → `event-after(fact i)` → 下一 fact，最後進入 `command-after`。三種 boundary 都可因 choice 跨 Snapshot 暫停，outer continuation 保存精確 fact/boundary cursor 與整筆 command 的 rollback checkpoint；hook-level queue 仍由 lifecycle dispatcher 保存。正常 command 與 command-before resume 都呼叫同一 pipeline，因此 reducer、facts、完成的 hooks、events 與 RNG 不會重複。

post-command 暫停期間 working state 可保留 reducer、已完成 hook 與 RNG 進度，但 revision／event log cursor 不提交。完整完成時只提交一次；任何後段 effect、unknown module/hook、registry mismatch 或 continuation validation 失敗，都回到原 command 起點且清除整組 pending state。Snapshot restore 會拒絕 cursor 越界、payload/context/registry 不一致、缺少配對 choice/queue、manifest 不相容與 recursive checkpoint。

`rules/combat-evaluator.ts` 是純且同步的討伐評估入口。`getLegalCommands` 與 `attackTarget` 都呼叫同一 evaluator，避免 query／dispatch 漂移；它依 distinct priority 解讀 Rules Module 的 JSON-only modifier、restriction 與 replacement records，驗證 module registry，並回傳 required combat、eligibility、outcome 與可稽核 rule refs。Evaluator 不執行 Effect AST、不消耗 RNG，也不載入卡牌專屬 policy；成功 dispatch 另產生 `COMBAT_EVALUATED` fact。

`rules/combat-reward-evaluator.ts` 與 `engine/combat-reward-pipeline.ts` 提供 CombatRewardPolicy registry 與可續跑 execution。它固定 defeated target、definition、encounter、recipient 與 ordered policy refs；choice 的 Snapshot cursor 恢復同一個 policy effect 再接續剩餘 policies，`remove-target` 不產生討伐獎勵。未載入任何卡牌獎勵資料。

`rules/equipment-eligibility-evaluator.ts` 以相同模式提供泛用裝備資格 boundary。`getLegalCommands` 與 `EQUIP_ITEM` reducer 使用同一個純 evaluator；Rules Module 只能註冊版本化 JSON restriction records，並以 explicit distinct priority、registry fingerprint 和結構化 rejection reason code 產生可重播結果。非法裝備 command 在 reducer/lifecycle mutation 前拒絕；choice 暫停與恢復沿用既有 command transaction，不載入任何卡牌、特定裝備效果或 continuous card effect。

`rules/team-overflow-evaluator.ts` 提供泛用 team capacity／overflow evaluation boundary；dispatch 與 evaluator 共用 JSON-only policy、priority、candidate IDs 與 registry fingerprint，不在 engine 寫死官方容量或官方預設處理。

`rules/encounter-resolution-evaluator.ts` 與 `engine/encounter-resolution.ts` 提供泛用 multi-target encounter boundary。Rules Module 只註冊 JSON-only resolution policy；純 evaluator 固定 target／attachment、health、completion 和 disposition plan，executor 在 transaction 中移動 target card／attachments 至 removed、shared-zone、module-zone 或 player-discard。Effect AST 的七個 encounter nodes 可組合 sequence、conditional、random 與 choice；Snapshot、lifecycle 及 post-command continuation 以 structured encounter payload 驗證 policy/registry，resume 不重跑已完成 mutation 或 RNG。這不包含任何正式/provisional 多部位魔王、官方 reward、終局或後續時序。

`rules/attack-resolution-evaluator.ts` 將 health target 接上同一個 authoritative `ATTACK_TARGET` boundary：Rules Module 的 JSON-only policy 明確提供 fixed damage 與 encounter disposition ref；legal query、command-before preview 與 reducer 共用 combat／party-prefix／damage evaluation。`ATTACK_RESOLUTION_EVALUATED` 與既有 encounter facts 一起進入 post-command pipeline；reward choice／consent 或 lifecycle 暫停可跨 Snapshot 恢復，後段錯誤回到 command checkpoint，且不增加 RNG 消耗。無 policy 時不把 health target 默認成一擊擊敗。

`rules/dice-evaluator.ts` 將 Rules Module JSON-only dice definition 與既有 RNG 分離：executor 只抽取一次 random value，純 evaluator 導出 face，並以 structured `DIE_ROLLED` event 保存結果；不存在卡牌或 UI 專屬骰子分支。

`rules/counter-consent-evaluator.ts` 與 Effect AST 的 `request-counter-consent` 提供泛用多 actor visibility lifecycle。Rules Module 只註冊 JSON-only policy；legal query 與 authoritative dispatch 共用 evaluator 的 actor／request／registry 判定。request 可跨 command-before、combat reward、event/command-after continuation 與 Snapshot 暫停，accept／decline／cancel／explicit expiration 從固定 cursor 恢復，整筆 command 完成後 revision／event cursor 只提交一次；後段失敗回到 command 起點。PlayerView 只投影已轉為 public 的其他玩家 counters，未載入任何 Vol.1 HP 或卡牌時序。

automatic overflow 與 player-choice overflow 都由 evaluator 的固定 candidate IDs 驅動；choice 使用既有 `RESOLVE_EFFECT_CHOICE` 與 command transaction，能跨 Snapshot 恢復。

Supply rows use Rules Module JSON-only configurations and shared deterministic refill/continuity evaluators. Base adventurer/item rows allow partial depletion; the monster row uses the approved three-card cycle-anchor project policy. No official physical composition is inferred.

Supply refresh is an Effect AST boundary: a JSON policy fixes row cards, destination ordering, and optional registered refill; no base/default refresh policy is loaded.

Continuous runtime is a pure evaluator over JSON-only Rules Module rules and source-instance presence. Query/dispatch consume the derived result, preventing repeated state mutation or RNG use.

### GameSession

- `LocalGameSession`：MVP 在 browser 內持有 authoritative state，呼叫 engine，經 storage port 存檔。
- `RemoteGameSession`：只持有 player view，command 送往伺服器，由 server room 執行 engine。
- feature UI 只依賴 session facade，不以 `if (online)` 分叉規則流程。
- local adapter 的 session update 另攜帶 `schemaVersion: 1`、JSON-only persistence status：`fresh`、`restored`、`saved` 或 `memory-only`，並綁定當下 revision 與 Replay history completeness。它只描述 adapter durability，不進入 GameState／Snapshot／Event，也不推進 revision；storage failure 與 `EngineError` 分流，已接受的 command 仍保留在記憶體內。
- session facade 同時產生 `schemaVersion: 1`、JSON-only entry summary，固定 game ID、round、phase、status、revision、Replay completeness 與是否可繼續。Web entry 只消費此摘要；繼續是純 UI transition，新遠征才呼叫既有 restart boundary，因此 React 不直接讀 localStorage 或重建 Snapshot 資訊。
- session update 可攜帶 versioned、JSON-only `ActionPreviewSet`，以 game ID、actor 與 revision 綁定 legal attack／purchase Command；adapter 必須在三者完全相符時才呈現。preview 是 pure query output，不進入 Snapshot、不消耗 authoritative RNG、不推進 revision。Effect 與 continuous preview evaluator 會先回報 randomness／hidden-information uncertainty；只有可從 PlayerView 完全推導時，deterministic command-before mutation 與精確 combat 才在 clone 上執行。RNG、隱藏抽牌／zone movement、未公開 module activation、隱藏 continuous source、未投影的 encounter／reward selection、choice 或 consent 都採保守可發現語意並回傳 `requires-lifecycle`，不得讓 legal Commands 或 payload 區分兩個相同 PlayerView。Snapshot invariant 額外禁止沒有 resolution policy 的 finished encounter；authoritative dispatch 仍會重新驗證同一套 combat、attack-resolution、combat-reward 與 purchase evaluators。

### ContentPack

- 基礎遊戲與擴充使用相同 manifest、definitions、replacements、Rules Modules 與 effect extension contract。
- engine 只接收驗證完成的 `ContentRegistry`，不 hard-code pack ID。
- server 只允許預先安裝且 hash 相符的 packs，client 不能上傳任意 handler。

### PresentationPack

- Presentation Pack 只依 stable definition ID 產出 display name、asset key、短文案與 theme／locale variant；不能包含 effect、數值、Command handler 或 Rules Module。
- React component 只能消費 resolver 輸出的 presentation view model；不得寫死人物名稱、圖片路徑或以顯示文字判斷卡種。
- 線上權威狀態不傳遞圖片；不同 client 可選不同 Presentation Pack。缺少 pack 時 client 使用中性 placeholder，不影響連線相容性。

### RulesModule

Rules Module 可提供設置變更、擴充專屬 zones、module state schema、供應牌庫耗盡處理、動態隊伍上限、敵方 encounters、結束條件、計分、visibility policies 與可序列化 lifecycle hooks。所有 module state 必須可序列化；可執行規則留在 engine，pending queue 只存版本化 ID 與純資料。

`rules/rules-module-composition.ts` 負責 optional module 的中央組合邊界。Core modules 是第一 tier；具 schema v1 composition metadata 的 optional modules 是第二 tier，依 distinct priority canonical 排序並驗證 dependency／exact version／conflict。Ruleset、GameState、Snapshot 與 Replay 共用 canonical composition fingerprint；呼叫端陣列順序不能改變 optional modules 的執行順序，也不能略過相依與衝突驗證。

`base:helpers` 是 opt-in optional module：Content Pack 只提供中性 helper definitions，setup contribution 依本局魔王數使用 authoritative RNG 建立 hidden helper deck；Supply Row contract 管理 active／retired 輪替；Boss defeat lifecycle metadata 觸發 refresh 與 capacity enforcement。Engine 不匯入 helper content package，也不 hard-code helper ID。

基礎版本身也是 Rules Module。Vol.1 疊加／替代基礎設置，將魔王數量改為玩家人數、註冊究極魔神 encounter、HP 隱藏資源與排名計分。engine 不包含 `if (vol1)`。

### Zone 與 Encounter

- 公共與玩家區域由 `ZoneId` + schema 表示，允許擴充新增區域。
- 冒險者／物資牌庫因實際補列抽取而成為空牌庫時產生一次正式 `SUPPLY_DECK_DEPLETED` Event；由 Rules Module 決定後續，不由 UI fallback。魔物以循環 policy 維持 committed 公開列正好 3 張，不產生耗盡事件。
- 敵方戰場是 `EnemyEncounterState` + 多個 `EnemyTargetState`，不是單一 `activeBossId`。
- 多部位究極魔神的每個部位可各自保存 HP、能力與擊敗狀態，整體完成條件由 module 聚合。

### Protocol

protocol schemas 包含 command envelope、player views、依 viewer 投影的 events、typed errors、content/rules manifests、Snapshot 與 Replay metadata。它不包含 React types、WebSocket client 或 database entity。

## 線上權威與隱藏資訊

- 線上房間的 `GameState` 只存在伺服器；client 不取得其他玩家手牌或牌序。
- 每個 command 包含唯一 `commandId` 與 `expectedRevision`；伺服器負責 actor 驗證、去重與 revision check。
- 成功後伺服器遞增 revision，依 viewer 產生裁切 view／events。
- 斷線重連先取得最新 snapshot/view，再接續更高 sequence 的 events。
- 網路重送不得造成重複購買、重複抽牌或重複結算。
- client animation 不決定規則結果；它只消費 server events。
- 隱藏 HP 等計數資源在伺服器投影時即移除／遮蔽，不把真實值傳給未授權 viewer。

MVP 雖無網路，local session 仍使用同一 command ID、revision 與 projection，提早測出線上化最昂貴的邊界。

## 擴充策略

- 新增擴充以新 `content-<pack-id>` package 為主，不修改 engine 中央 switch。
- 卡片替換在 registry composition 時依 stable ID／version 解析，不在遊戲中以同名搜尋。
- 通用新機制先加 declarative primitive；只有特殊例外使用 namespaced extension handler。
- setup、牌庫組合、擴充 zones、module state、可選規則與 content conflicts 由 pack manifest／Rules Modules 描述。
- 隊伍上限、結束條件與 scoring pipeline 都是可組合 policies，不寫死 5 人、兩個結束條件或單一計分公式。
- 對局開始後鎖定 ruleset、packs、versions 與 hashes。
- replay／save 若缺少相同內容版本，不允許靜默以新版載入；必須 migration 或明確標示不相容。

## AI 策略

- AI 是另一種 actor，透過 legal commands 送出相同 command envelope。
- AI 只讀對應玩家的 `PlayerView`，不得讀完整 GameState 作弊。
- 評估與搜尋可在 Web Worker 或 server worker 執行，不進 React render path。
- AI 難度與策略是 `game-ai` package 的責任，不在 rules engine 放啟發式判斷。

## 儲存與重播

存檔／server snapshot 至少包含：

- schema 與 ruleset version
- content pack manifests、versions 與 hashes
- seed 與可序列化 RNG state
- authoritative GameState（僅安全儲存端）
- revision 與必要 command/event 診斷紀錄
- 各 Rules Module 的版本化可序列化 state
- 所有 zones、encounters、targets、玩家計數資源與 visibility policy state
- pending effect choice 與 lifecycle queue 的 payload、context、剩餘 hooks、版本指紋及 rollback checkpoint

localStorage、IndexedDB 與 server database 都是 repository adapters。engine 不知道資料存在哪裡。

本機成功寫入後才回報 `saved`；合法讀回 current v3 或 legacy save 時回報 `restored`，並保留實際 Replay completeness。寫入例外只把 adapter 狀態改為 `memory-only`，不製造 `INVALID_COMMAND`，因此 UI 可給出耐久性警告而不混淆規則結果。

## 防止過度設計

完整架構不代表現在實作所有功能：

| 現在必須完成 | 延後到需要時 |
| --- | --- |
| workspace package boundaries | WebSocket server 與 room scaling |
| pure deterministic engine | database／cache 選型 |
| content pack contract | 實際擴充卡牌資料 |
| Rules Module、Zone、Encounter、Scoring contracts | Vol.1 規則的實際啟用 |
| Effect AST、choice、lifecycle continuation、generic combat 與 equipment eligibility evaluation | 正式／provisional 卡牌效果、卡牌專屬討伐獎勵、特定裝備效果、泛用供應列與 continuous 卡牌效果 |
| player projection | 登入、邀請、觀戰產品流程 |
| command ID/revision | 跨節點鎖與分散式部署 |
| local GameSession adapter | remote adapter implementation |
| versioned save metadata | 長期 replay 儲存策略 |

原則是「現在建立穩定接縫，未來再補 adapter」，不是「現在模擬尚未存在的後端」。

## 架構驗證

M0 的 `check:architecture` 必須驗證 workspace dependency graph、禁止 deep import、循環依賴、檔案大小與複雜度。contract tests 必須涵蓋 Rules Module composition、Snapshot／Replay compatibility，並讓 local session 與日後 remote session 共用同一套行為規格。
