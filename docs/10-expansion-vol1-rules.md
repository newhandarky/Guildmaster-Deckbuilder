# 第一擴充 Vol.1 正式規則規格

本文件依官方《擴充包 Vol.1 說明書》8 頁整理。擴充規則建立在基礎版之上；未被本文件修改的部分仍依 `01-game-rules.md`。個別究極魔神的詳細能力以其魔神卡與玩家效果卡為準。

## 1. 擴充內容

| 類別 | 數量 |
| --- | ---: |
| 冒險者卡（包含轉職冒險者） | 20 |
| 追加物資卡 | 12 |
| 追加魔物卡 | 6 |
| 追加魔王卡 | 1 |
| 魔神卡 | 20 |
| 首刷替換卡 | 13 |
| 榮譽值卡 | 3 |
| 血量標記 | 30（1、5、10） |

擴充中的冒險者、物資、魔物與魔王加入基礎版的同種類牌庫使用。魔神卡只在本擴充規則啟用時使用。

## 2. 轉職冒險者與追加卡牌

- 轉職冒險者仍屬冒險者卡，使用冒險者牌庫、招募區、隊伍與公會區域的一般規則。
- 追加物資加入物資牌庫；追加魔物加入魔物牌庫；追加魔王加入可供本局抽選的魔王集合。
- 魔神卡效果判定時，究極魔神視同魔王；若個別卡片或本規則另有明確差異，依較具體規則處理。
- 卡片 ID、來源 pack 與版本必須保留，不能只靠顯示名稱區分基礎版、追加卡與替換卡。

## 3. 首刷替換卡

- 首刷替換卡用來替換首刷基礎版中的同名卡牌。
- 被替換的舊版本不再加入該內容組合；不是把新版與舊版同時混入牌庫。
- 數位內容組合階段依穩定卡片 ID 與 `replaces` 關係解析替換，不以顯示名稱或執行中移除實例的方式處理。
- 存檔與 Replay 必須記錄實際使用的卡片版本／content hash，避免舊局靜默改用新版效果。

## 4. 擴充模式設置

在基礎版設置上修改／增加：

1. 本局魔王卡數量改為「玩家人數」，不再是玩家人數 + 2。
2. 選擇本局使用的 1 名究極魔神。
3. 將該究極魔神的 4 張魔神卡置於魔王牌庫底。
4. 依所選究極魔神的血量，將對應數量的血量標記放在一旁備用。
5. 遊戲開始時，發給每位玩家該究極魔神的效果卡，用來確認能力與討伐策略。

`GameConfig` 必須記錄啟用的擴充 Rules Module、究極魔神 ID、魔神部位 IDs、血量設定與內容版本。

## 5. 究極魔神出現

滿足任一條件時，究極魔神登場：

1. 最後一隻魔王被擊敗。
2. 冒險者牌庫被抽空。
3. 物資牌庫被抽空。

登場時，將設置時預留的血量標記置於魔神卡上。

### 5.1 供應牌庫耗盡事件

- 冒險者或物資公共供應牌庫因抽取而變成空牌庫時，引擎先產生 `SUPPLY_DECK_DEPLETED`，再由 Vol.1 Rules Module 判定究極魔神登場。
- 這不是個人牌庫重建，也不是 UI 補牌失敗 callback。
- 只要該事件符合本擴充的條件即可觸發；不得把「查看／展示個人牌庫頂」與公共供應牌庫抽空混為一談。
- 官方勘誤另指出：冒險者牌庫抽空時，【機械魔神】右手部位的效果不會觸發。
- 基礎版沒有公布相同的究極魔神結果；未啟用本 Rules Module 時不可套用本節。

## 6. 討伐究極魔神

### 6.1 選擇討伐

1. 討伐階段開始時，先結算隊伍中「討伐階段開始時」的效果。
2. 玩家之後可以選擇討伐究極魔神。
3. 若選擇討伐究極魔神，本回合在其前後都不能再討伐魔物或魔王。

### 6.2 結算

1. 宣告討伐魔神後，計算隊伍當前總戰力。
2. 從魔神卡上拿取與總戰力相同數量的血量標記，放入該玩家自己的隊伍區域。
3. 若總戰力大於魔神剩餘血量，只拿取實際剩餘的血量標記。
4. 將隊伍內所有冒險者連同其配戴裝備置入棄牌堆。
5. 取得其討伐獎勵。
6. 結束本次討伐階段。

與一般討伐只派遣「達標前綴」不同，究極魔神規則會計算整支當前隊伍並將隊伍內所有冒險者與裝備置入棄牌堆。個別魔神卡若改變此流程，以卡片／效果卡為準。

### 6.3 擊敗與遊戲結束

- 魔神卡／部位被擊破時，依該究極魔神的規則處理卡片取得與榮譽值；部位擊破事件不等於整體究極魔神已被擊敗。
- 只有達成所選究極魔神效果卡規定的整體擊敗條件，才產生 `ULTIMATE_DEMON_DEFEATED` 並觸發遊戲結束。一般規則與【機械魔神】「四部位全部擊破」的覆寫不得混成單一判定。
- 官方一般規則指出，擊敗魔神的玩家取得該魔神卡，其榮譽值加入計分；多部位卡的取得時點仍須依各魔神卡／效果卡執行。
- 遊戲仍完成當前輪次，直到起始玩家右手邊玩家的回合結束，與基礎版終局輪規則一致。

## 7. 多部位究極魔神

- 究極魔神由 4 張魔神卡組成；各張卡是可獨立建模的敵方目標／部位，不得只用單一 `activeBossId` 表示。
- 每個部位可有自己的血量、榮譽值、被動能力、擊敗狀態與效果資料。
- 部位與整體魔神分開判定；只有符合該究極魔神效果卡所列條件時，才算整體被擊敗。

### 7.1 【機械魔神】

- 本體分為 4 個部位。
- 每個部位血量獨立，且有獨特被動能力。
- 部位尚未被擊敗時，其被動能力持續生效；不論該回合是否選擇討伐機械魔神。
- 擊敗全部 4 個部位才算擊敗機械魔神。
- 每個部位血量為 20、榮譽值為 2。
- 個別部位擊破與整體擊敗必須分別發出事件；前三個部位擊破不得提前進入終局輪。

### 7.2 其他究極魔神

官方說明書另展示【混沌龍神】柯羅諾斯與【詛咒蛇神】梅杜莎；其牌組同樣由多張魔神卡組成，但戰場規則、血量處理與能力依各自魔神卡及效果卡執行。文件未取得可逐字結構化的完整效果卡內容前，不得自行推測部位選擇、傷害分配或特殊勝敗流程。

## 8. 血量標記資訊

- 玩家取得的血量標記預設為非公開資訊。
- 只有所有玩家都同意時，才可改為公開資訊處理。
- 資訊可見性屬 Rules Module 的 resource visibility policy；線上模式不得先把數值傳給其他 client 再只用 CSS 隱藏。
- 每位玩家的血量標記是可序列化計數資源，須記錄來源究極魔神／部位與取得事件。

## 9. 榮譽值與血量排名

遊戲結束時，除基礎版一般榮譽計分外：

1. 所有玩家公開自己取得的血量標記總值。
2. 依總值比較排名並取得額外榮譽值：第一名 20、第二名 14、第三名 8。
3. 沒有取得任何血量標記（HP 為 0）的玩家不參與排名，也無法取得排名榮譽值。

### 9.1 同分平均

同分玩家並列，將其占用名次的榮譽值相加後平均分配：

- 兩名玩家並列第一：第一、第二名獎勵 `(20 + 14) / 2 = 17`，兩人各得 17；下一位為第三名，得 8。
- 三名玩家同分並列：前三名獎勵 `(20 + 14 + 8) / 3 = 14`，三人各得 14。

官方說明書沒有列出所有四人同分排列、第三名與無獎勵名次並列時的完整算例，也未說明非整數平均的捨入方法。這些情況保留為 open question，不可自行推測。

## 10. 擴充勘誤與 FAQ

### 10.1 血量標記公開性

取得的血量標記原則上是非公開資訊；所有玩家同意時可公開。

### 10.2 討伐魔神時的裝備移除

主遊戲裝備「真龍斧連枷」、「絲綢緞帶」在實際用於討伐魔神後也會依規則移除。若裝備在討伐結算前已因其他效果離場，就不視為本次討伐中實際使用過，不會只因究極魔神討伐成功而移出遊戲。

### 10.3 隊伍上限降低

若冒險者／裝備離場或其他效果使目前隊伍人數上限降低，而隊伍人數超過新上限：

1. 從隊伍最末端，也就是最右側冒險者開始處理。
2. 將該冒險者與其配戴裝備置入棄牌堆。
3. 重複直到隊伍人數不超過目前上限。

隊伍上限因此必須是可由效果修改的衍生值，不能寫死為 5。

### 10.4 供應牌庫與特定效果

- 冒險者牌庫抽空時，【機械魔神】右手部位效果不會觸發。
- 「展示牌庫頂」與「抽牌」不同；展示數量不足只展示剩餘牌，不重建牌庫。

### 10.5 莉茲米 A

效果發動時，若左手邊玩家沒有其他冒險者卡，不結算後半段效果，也不將任何卡置入我方棄牌堆。

### 10.6 討伐階段結束時效果

蘿絲瑪麗、莉茲米、尤伊爾或裝備靈能之杖等在討伐階段結束時發動的效果，若在時點到來前已不在隊伍中，就不能發動；除非卡片另有說明。

### 10.7 禁止過量派遣

一般討伐一旦戰力足夠，就不能再額外派遣冒險者並置入棄牌堆。

### 10.8 「此回合中」效果

加入隊伍時觸發且標示「此回合中」的效果，即使來源稍後離開隊伍，仍持續至該回合結束。

### 10.9 巫妖

若隊伍戰力達標並選擇討伐，且冒險者／裝備已置入棄牌堆與觸發效果後，手牌仍沒有可捨棄的冒險者，巫妖留在公共區域且無法取得報酬。

## 11. 正式事件與規則擴充點

Vol.1 至少需要下列事件／政策：

- `SUPPLY_DECK_DEPLETED`
- `ULTIMATE_DEMON_APPEARED`
- `ULTIMATE_DEMON_ASSAULT_DECLARED`
- `ULTIMATE_DEMON_HP_CLAIMED`
- `ULTIMATE_DEMON_PART_DEFEATED`
- `ULTIMATE_DEMON_DEFEATED`
- `PARTY_LIMIT_CHANGED`
- `PLAYER_COUNTER_VISIBILITY_CHANGED`
- `END_CONDITION_TRIGGERED`
- `RANKING_SCORE_AWARDED`

事件名稱是架構規格，不要求玩家顯示英文。Rules Module 必須以可序列化 state 與純 handler 實作，不把擴充規則散落在 UI。
