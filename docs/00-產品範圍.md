# 產品範圍

## 產品目標

建立一款可在桌面與平板瀏覽器遊玩的完整牌庫構築遊戲平台。最終產品支援基礎遊戲、獨立內容擴充包、AI 對手、離線同機與伺服器權威的線上對戰；美術主題可以在不改動規則引擎的情況下替換。

MVP 先實作基礎遊戲的離線「一位真人玩家 + 一位 AI 對手」流程，但它只是完整架構上的第一個交付切片，不是另一套臨時架構。

## 兩層範圍

### 完整產品目標

- 基礎遊戲與多個可組合、可版本化的內容擴充包
- 離線 2–4 人 hot-seat
- 一位玩家搭配 AI 對手的真正單人模式
- 房間制線上對戰、斷線重連與對局恢復
- 伺服器權威規則驗證，客戶端不可信任
- 相同規則引擎同時供本機、AI、測試與伺服器使用
- 依玩家身分裁切資訊，避免在線上模式洩露手牌與牌庫順序
- 對局版本、內容包 manifest、snapshot 與 command log 可追蹤

### MVP 交付範圍

MVP 只縮小功能，不縮小架構。第一版不啟動 server、AI 或擴充包，但必須使用它們未來會共用的 engine、content pack、protocol 與 session contracts。

## 目標玩家

- 已熟悉原桌遊、希望快速開局的玩家
- 想學習規則、需要系統引導合法操作的新玩家
- 想以 AI 對手進行單機遊玩的玩家（MVP）
- 同一台裝置上的 2–4 位玩家（後續啟用）
- 透過私人房間遠端對戰的 2–4 位玩家（後續）

## MVP 包含

- 一位真人玩家與一位 AI 對手的離線單機對局
- 開局設定、隨機種子與起始玩家
- 酒館四個供應區：冒險者、物資、魔王、魔物
- 玩家牌庫、手牌、棄牌堆、隊伍、裝備、使用區與羈絆狀態
- 行動一、討伐、行動二、購買、休息五階段
- 完整基礎遊戲卡牌機制資料
- 合法操作提示、效果選擇視窗、撤銷尚未提交的 UI 選擇
- 勝利條件、終局輪、榮譽計分與平手判定
- 自動存檔與讀檔
- 規則說明、操作紀錄與可重現的隨機種子

## MVP 不包含

- 網路連線、帳號、配對、排行榜
- 多位真人玩家的 hot-seat UI
- 擴充卡牌
- 進階協助者規則
- 羈絆輪抽規則
- 官方圖片、卡面掃描或官方版面重製
- 商店、付費或公開發行流程

「不包含」表示當期不提供可操作功能，不表示可以把規則寫進 React、假設永遠只有基礎卡，或讓 UI 直接讀完整隱藏狀態。

## 重要用語

本專案的「單機」指不需要伺服器。本 MVP 啟用一位真人玩家對抗 AI；底層仍採一般化玩家座位與 `PlayerView`，日後可加入 hot-seat，不需重寫規則引擎。

## 成功標準

MVP 可以視為完成，需同時滿足：

1. 一位真人玩家與 AI 可從設定一路玩到結算，沒有必須改資料才能繼續的阻斷狀態。
2. 官方勘誤與核心 Q&A 案例都有自動測試。
3. 相同 seed 與相同指令序列會得到相同結果。
4. 重新整理頁面後可恢復最近一局。
5. 所有官方圖像均未進入 repository 或正式 build。
6. 手機橫向、平板與桌面可完成所有操作；M6 已以 1280×800、1024×768、667×375 與 320px（150% 文字）Playwright 回歸核心流程與整頁無水平溢位，但尚未宣稱完整 WCAG 合規或完成跨瀏覽器／手動 assistive-technology audit。
7. MVP 透過 `GameSession` contract 操作，不直接綁定 localStorage 或本機 engine instance。
8. 基礎卡以 `ContentPack` 載入；engine 不 hard-code `base` 或任何擴充 ID。
9. UI 只接收目前 viewer 的投影資料，不直接依賴完整 `GameState`。

## 後續方向

- Phase 2：協助者、羈絆輪抽與內容包擴充
- Phase 3：強化既有 AI 的策略、難度與 worker 執行
- Phase 4：加入 remote session adapter、權威伺服器、房間與斷線重連；共享規則引擎直接部署至伺服器，不進行搬移或重寫
- Phase 5：主題、美術、音效與無障礙強化
