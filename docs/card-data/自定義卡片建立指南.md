# 自定義卡片建立指南

本文件說明在此專案建立自定義卡片時，需要先準備哪些資料，以及哪些欄位可以直接轉成目前 Runtime 的 `CardDefinition`。

目前權威契約位置：

- `packages/game-protocol/src/cards.ts`：卡片與內容包資料結構。
- `packages/game-protocol/src/effects.ts`：可序列化效果語言。
- `packages/game-protocol/src/lifecycle.ts`：階段、事件與裝備觸發。

## 一、設計卡片時必須提供的資料

以下是「作者資料表」的最低要求。即使部分欄位不會直接存入 `CardDefinition`，也必須寫清楚，才能判斷 Engine 是否已支援該效果。

### 1. 身分與顯示

| 屬性 | 必填 | 說明 | 範例 |
|---|---|---|---|
| `id` | 是 | 全域唯一、穩定、不可改名的 namespaced ID；只用小寫英文、數字、`-`、`/`、`:`。 | `custom:resource/fire-potion` |
| `name` | 是 | 顯示名稱。 | `烈焰藥水` |
| `type` | 是 | 卡種；常用值為 `starter`、`adventurer`、`item`、`equipment`、`monster`、`boss`、`bond`、`helper`。 | `item` |
| `copies` | 是 | 內容包中要建立的實例數；非負整數。 | `2` |
| `source` | 是 | 來源或內容包識別；自製卡不要標成官方來源。 | `custom-playtest` |
| `art` | 建議 | 圖檔、作者、授權與裁切資訊。此欄目前不在 `CardDefinition`，由 Presentation／素材清單保存。 | `assets/cards/fire-potion.webp` |
| `rulesText` | 是 | 玩家實際閱讀的完整卡面文字。此欄目前不直接進 Runtime，需另由 Presentation 保存。 | `抽 2 張牌。` |

### 2. 卡面數值

| 屬性 | 適用卡種 | 說明 |
|---|---|---|
| `cost` | 冒險者、道具、裝備 | 公共供應區的印刷費用；整數且通常不小於 0。 |
| `combat` | 冒險者、裝備、魔物、魔王 | 印刷戰力；暫時加減值不可寫回此欄。 |
| `purchasePower` | 起始資源、魔物、魔王 | 該卡進入玩家牌組後可提供的印刷購買力。 |
| `honor` | 冒險者、道具、裝備、魔物、魔王、羈絆 | 終局榮譽值。 |
| `profession` | 冒險者 | 目前以 tag 表示：`profession:melee`、`profession:tank`、`profession:ranged`、`profession:support`、`profession:mage`。 |
| `itemEffect` | 舊式示範道具 | 只接受 `purchase+2` 或 `combat+2`；新卡應優先使用 `useEffect`，不要擴大這個 legacy 欄位。 |

不適用的數值請省略，不要填 `null`，也不要為了湊欄位填 0。例如純道具通常沒有 `combat`。

### 3. 效果規格

每個效果都必須回答以下問題：

| 屬性 | 必填 | 說明 |
|---|---|---|
| `timing` | 是 | 何時可以發動：行動階段、討伐開始、擊敗後、討伐結束、購買開始、休息、回合開始／結束、進場、離場等。 |
| `controller` | 是 | 誰控制效果；通常是卡片擁有者或當回合玩家。 |
| `optional` | 是 | 玩家控制的可選一次性效果是否可略過。持續被動、限制、位置檢查與明示強制效果不可用此欄位關閉。 |
| `activationCondition` | 是 | 發動前必須成立的條件。沒有條件時明寫 `always`。 |
| `cost` | 是 | 發動後必須先支付的成本，例如棄 1 張牌。沒有成本時明寫 `none`。 |
| `target` | 是 | 可選目標的玩家、區域、卡種、職業、數量上下限與公開資訊限制。沒有目標時明寫 `none`。 |
| `resolution` | 是 | 依順序列出每一步狀態改變。不要只寫「處理卡片效果」。 |
| `zeroCandidate` | 是 | 沒有合法目標時：不能發動、直接略過，或仍執行不需要目標的部分。 |
| `duration` | 是 | `immediate`、`this-phase`、`this-combat`、`this-turn`、`until-rest` 或 `while-source-present`。 |
| `destination` | 視效果 | 卡片最後去手牌、棄牌堆、牌庫頂／底、共享區、附著區或移出遊戲。 |
| `visibility` | 是 | 私下查看或公開展示；需要其他玩家驗證卡種時必須公開。 |
| `ordering` | 是 | 與其他效果同時觸發時由誰排序；目前同一玩家控制的效果由該玩家決定順序。 |
| `decisionKind` | 有選擇時 | CPU 與 UI 使用的選擇語意，例如棄牌、移除、回收、選市場牌、選敵人、選隊員、輪抽、傳牌。 |
| `failure` | 是 | 無法支付成本、規則資料缺失或 mutation 失敗時，要 fail closed 並回滾到 command 前。 |

## 二、目前 Runtime 的 `CardDefinition`

目前程式真正接受的基本形狀如下：

```ts
type CardDefinition = {
  id: string;
  name: string;
  type: string;
  copies: number;
  cost?: number;
  combat?: number;
  purchasePower?: number;
  honor?: number;
  itemEffect?: "purchase+2" | "combat+2";
  useEffect?: EffectDefinition;
  equipmentEventTriggers?: readonly EquipmentEventTrigger[];
  source: string;
  tags?: string[];
};
```

注意事項：

- `type`在型別上是開放字串，但新卡種若沒有對應 Zone、Supply Row、Legal Commands 與 Rules Module，仍不能直接遊玩。
- `name`是 Runtime 顯示名；若來源有版權或尚未確認，請使用中性測試名稱，另在 Presentation 保存顯示文案。
- `copies`、所有數值與效果資料都必須是可序列化、有限且可驗證的資料。
- `tags`用於職業、效果啟用狀態、親和性與專案證據，例如 `profession:mage`、`playtest:effect-enabled`。
- 只有把卡片加入 `ContentPack.definitions`並建立相應供應／設置規則，遊戲才會生成其實例。

## 三、可用的效果動作

`useEffect`使用 `EffectDefinition`：

```ts
type EffectDefinition = {
  schemaVersion: 1;
  effectId: string;
  body: EffectNode;
};
```

目前 `EffectNode`可表達的主要能力：

- 流程：依序執行、條件分支、玩家選項、選擇卡片、隨機結果、擲骰。
- 卡片：移動、抽牌、棄牌、移出遊戲、轉移所有權。
- 數值：本回合購買力、本回合戰力、玩家 counter。
- 戰鬥獎勵：抽牌、購買力、戰力、counter。
- 共享區：刷新供應列、收斂隊伍容量。
- 遭遇：建立遭遇／敵方目標、附著卡片、傷害、擊敗、移除與結束遭遇。
- 多人：請求 counter consent。

選卡來源目前只允許：

- 自己或指定玩家的 `hand`、`discardPile`、`playArea`。
- 指定玩家的 `party`。
- 上述區域的有限組合。

不可讓一般玩家選擇隱藏牌庫中的特定卡；隨機與抽牌必須由 Engine 的權威 RNG 處理。

## 四、可直接複製的作者資料範本

這份 YAML 是設計／審查用資料，不是可直接匯入 Runtime 的 schema。

```yaml
schemaVersion: 1
id: custom:resource/example-card
name: 自製卡片名稱
type: item
copies: 2
source: custom-playtest

printedStats:
  cost: 3
  combat: null
  purchasePower: null
  honor: 1

tags:
  - playtest:effect-enabled

presentation:
  rulesText: "棄 1 張手牌後，抽 2 張牌。"
  artPath: null
  artCredit: null
  license: null

effectSpec:
  effectId: custom:effect/example-card/use
  timing: action
  controller: card-owner
  optional: true
  activationCondition: hand-has-at-least-1-other-card
  cost:
    action: discard-card
    count: 1
    from: hand
  target: self
  resolution:
    - action: draw
      count: 2
  zeroCandidate: cannot-activate
  duration: immediate
  visibility: private-hand-public-action
  ordering: controller-choice
  decisionKind: discard-card
  failure: rollback-command

implementation:
  engineCapability: choose-card-then-draw
  cpuResolver: discard-lowest-utility
  normalPathTest: null
  zeroCandidateTest: null
  snapshotTest: null
  rollbackTest: null
```

## 五、對應的 Runtime 範例

以下示範「玩家可選擇不使用；若使用，必須先棄 1 張手牌，才能抽 2 張」。`skip`選項用來落實效果可略過的規則。

```ts
const exampleCard: CardDefinition = {
  id: "custom:resource/example-card",
  name: "自製卡片名稱",
  type: "item",
  copies: 2,
  cost: 3,
  honor: 1,
  source: "custom-playtest",
  tags: ["playtest:effect-enabled"],
  useEffect: {
    schemaVersion: 1,
    effectId: "custom:effect/example-card/use",
    body: {
      kind: "choice",
      choiceId: "custom:choice/example-card/use-or-skip",
      decisionKind: "choose-effect-option",
      actor: { kind: "controller" },
      options: [
        {
          id: "use",
          effect: {
            kind: "choose-card",
            choiceId: "custom:choice/example-card/discard-cost",
            decisionKind: "discard-card",
            actor: { kind: "controller" },
            from: {
              kind: "player-zone",
              player: { kind: "controller" },
              zone: "hand"
            },
            selectedCardKey: "discarded-card",
            effect: {
              kind: "sequence",
              effects: [
                {
                  kind: "discard-card",
                  card: { kind: "context-card", key: "discarded-card" },
                  from: {
                    kind: "player-zone",
                    player: { kind: "controller" },
                    zone: "hand"
                  }
                },
                {
                  kind: "draw",
                  player: { kind: "controller" },
                  count: 2
                }
              ]
            }
          }
        },
        {
          id: "skip",
          effect: {
            kind: "conditional",
            condition: { kind: "always", value: false },
            whenTrue: {
              kind: "draw",
              player: { kind: "controller" },
              count: 0
            }
          }
        }
      ]
    }
  }
};
```

範例只展示資料形狀。正式加入內容包前，仍須確認「使用中的道具本身是否已離開手牌／進入 playArea」，避免把該卡誤列為可支付的棄牌成本。

## 六、內容包屬性

自定義卡片應放進獨立 `ContentPack`，不要直接修改既有 base pack：

| 屬性 | 說明 |
|---|---|
| `manifest.id` | 內容包 namespaced ID，例如 `custom:my-cards`。 |
| `manifest.version` | 語意化版本，例如 `0.1.0`；效果或數值改動應升版。 |
| `manifest.hash` | definitions 與行為資料的內容雜湊；修改內容後必須更新。 |
| `manifest.role` | `base`或`expansion`；自製追加卡通常是 `expansion`。 |
| `manifest.contentStatus` | 自製測試內容使用 `provisional-playtest`。 |
| `manifest.dependencies` | 精確列出依賴的 pack ID／版本。 |
| `definitions` | 本內容包的所有 `CardDefinition`。 |
| `starter` | 只有內容包要提供起始設置時才填。 |
| `bonds` | 羈絆的 ID、名稱、榮譽與目前支援的簡化條件資料。 |
| `rulesModuleIds` | 卡片依賴的 Rules Module ID。 |

## 七、加入遊戲前的驗收清單

- [ ] ID、effect ID、choice ID、trigger ID 全部唯一且無前後空白。
- [ ] 名稱、卡種、張數、費用、戰力、購買力、榮譽已填妥或明確標示不適用。
- [ ] 完整卡面文字與圖示意義已由第二人覆核。
- [ ] 效果的時點、控制者、可選性、成本、目標、零候選、目的地與持續時間已定義。
- [ ] 不會讀取玩家不應知道的隱藏牌庫順序。
- [ ] 所有效果都能由現有 Effect AST／Rules Module 表達；否則先標記 `playtest:effects-disabled`。
- [ ] 每個必要選擇都有 UI 與 CPU `decisionKind`／resolver。
- [ ] 有 normal、skip、zero-candidate、Snapshot round-trip、rollback 與 Replay 測試。
- [ ] 卡片已加入獨立 ContentPack，並更新 pack version 與 hash。
- [ ] Ruleset validation、content validation、typecheck 與 focused tests 全部通過。

## 八、什麼情況不能只新增一筆卡片資料

下列能力若目前沒有通用規則，必須同時擴充 Protocol／Engine／CPU／Web，不能在 React 裡直接改 `GameState`：

- 新卡種或新公共區域。
- 新階段、全新觸發 boundary 或跨回合持續狀態。
- 多人輪選、跨玩家傳牌、公開／私密展示的新語意。
- 新的裝備限制、多重附著或敵方附著方式。
- Engine 尚未支援的新隨機方式。
- CPU 無法理解的必要 choice。

遇到上述情況，先把卡片標記為效果未啟用，完成權威規則與測試後再開啟。
